# ganja-code

## Purpose

`ganja` is a terminal-first AI coding agent: a **behavioral port of [opencode](https://github.com/anomalyco/opencode) v1.18.22 to Rust**, with a ratatui TUI. Upstream's TypeScript is the *specification*, not source to translate — the port writes idiomatic Rust and matches observable behavior. The workspace is fourteen members: the protocol, the permission engine, the teams directory, the tools, the provider wires and the session store beneath an engine that carries no terminal dependency, then `ganja-teammate-local` — the tmux-pane and foreign-CLI teammate backends, sitting *above* that engine the way a frontend does — a ratatui frontend, an HTTP frontend, the client that attaches to it, and the `ganja` binary that wires them together — plus `ganja-testkit`, dev-only scaffolding that no shipped binary links, and the sealed-leaf `tmux` as a fourteenth member deliberately outside that dependency chain: it is neither a frontend nor beneath the engine, and nothing described here consumes it.

The dependency boundaries are `depgate.toml` at the repository root, evaluated by `cargo depgate check` (zchee/cargo-depgate, installed in CI pinned by commit): nineteen rules — five deny rules (the engine reaches no `ratatui*` and no `axum*`; a wire reaches no `ratatui*`, `crossterm*` or `arboard*` — no terminal and no clipboard; the terminal frontend never grows `axum*`; the HTTP frontend never grows `ratatui*` or `ganja-teammate-local`, because a worker's closure excludes panes and shims; the client never grows `axum*`), seven exact internal-dependency allowlists (tool = permission; team = protocol; storage = the two leaves; provider = permission, protocol, tool; core = the six beneath it; client = protocol; teammate-local = core plus those six) which fail closed where a `! grep` would not, three leaf rules (`ganja-permission` and `ganja-protocol` need nothing of ours, and the sealed `tmux` consumes none of ours), two exact depth-1 direct-dependency sets (`ganja-protocol` = serde, serde_json, uuid; `tmux` = futures, thiserror, tokio — the leaf shape sees only internal names, so an external widening needs its own rule), the sealed rule that no other workspace member consumes `tmux` (over the member set resolved at gate time), and the manifest rule that every dependency version lives in the root manifest. Together they assert every direction that matters — the engine reaches no terminal, nothing beneath the engine reaches the engine, and the bottom crates stay leaves; each rule's rationale and the shell step it retired are comments in `depgate.toml` itself.

Single tests (nextest filters by name substring; `cargo test` still works and is what runs doctests):

```sh
cargo nextest run -E 'binary(golden)'                # one integration binary
cargo nextest run -E 'binary(mcp)'                   # shares golden's bun + upstream-checkout prerequisites
cargo nextest run -E 'binary(lsp)'                   # needs rust-analyzer on PATH (rustup component); hard-fails without it
cargo nextest run -p ganja-permission                # the permission engine's own tests
cargo nextest run -p ganja-provider                  # the wires, the logins and the catalog
cargo nextest run --workspace permission             # every test whose name matches "permission"
cargo nextest run -p ganja-tui snapshot_tool_error   # one snapshot test

```

Two suites need setup, and both are documented in `crates/ganja-core/tests/AGENTS.md`:

- **Golden differential** runs in the default test run (`cargo nextest run`, or `cargo test`) and **hard-fails rather than skips** when its prerequisites are missing — a green run that compared against nothing would be worthless. It needs `bun` on `PATH` and an upstream checkout with `bun install` already run, at `.omc/reference/opencode-v1.18.22` or wherever `GANJA_OPENCODE_DIR` points (CI checks it out to `upstream/`). The MCP suite (`tests/mcp.rs`) shares those prerequisites — its reference server runs on the checkout's installed `@modelcontextprotocol/sdk` — and hard-fails the same way.
- **Live provider tests** are `#[ignore]`d *and* inert unless opted in: `GANJA_LIVE_TEST=1 ANTHROPIC_API_KEY=… cargo test -p ganja-core --test live -- --ignored`.

## Architecture

Fourteen members — twelve crates that ship, plus dev-only `ganja-testkit` (the fixture doubles `crates/ganja-core/tests/*.rs` share; a `[dev-dependencies]` entry and nothing else, so no shipped binary links it), plus the sealed-leaf `tmux`, deliberately outside that dependency graph and neither consumed by nor consuming any of its members (P26 user directive, 2026-08-18). The count is `cargo metadata --no-deps`'s, not a hand tally. The load-bearing boundaries are asserted rather than trusted: nothing in the engine may reach a terminal or an HTTP server, nothing beneath the engine may reach the engine, and the two bottom crates name nothing else of ours. The graph is a DAG, not a chain — frontends and `ganja-teammate-local` alike sit on `ganja-core` (**D539**: the teammate backends are assembled by a caller and handed in, the way a frontend assembles everything else an `Engine` needs, rather than built by the engine itself), core on `ganja-provider`, `ganja-storage`, `ganja-tool` and `ganja-team` — `ganja-provider` and `ganja-storage` on both bottom leaves, `ganja-tool` on `ganja-permission` alone, `ganja-team` on `ganja-protocol` alone (**D540** put the new crate exactly where `ganja-provider` already stood) — while `ganja-protocol` is a leaf that core, the provider crate, the teams crate, the storage crate, the frontends, `ganja-teammate-local` and `ganja-client` consume directly and that tool and permission never touch. Every "nothing beneath may reach the engine" claim is an **allowlist** rule in `depgate.toml` — the policy file CI's `cargo depgate check` evaluates — rather than a blocklist, because a blocklist names one crate and goes quiet the day a new one appears.

Each member is summarized here with the boundary CI asserts for it and the decisions it owns. Where a member's full account outgrew this file's own 150,000-character budget it lives in that crate's `AGENTS.md` — `ganja-tool`, `ganja-tui`, and `ganja-core`'s teammate subsystem — which an agent working in that subtree is handed anyway; nothing was summarized away, only moved, and each summary names where its decisions are stated in full.

**`ganja-protocol`** — the types every side of the app speaks: `Command`, `Event`, `Message`/`Part`, `ToolState`, `Usage`, and the ids that sort in creation order. Serde-derived from day one; that serialization constraint — not a trait — is what preserves the path to serving the engine over a socket and to transcripts that replay from disk. Its dependency list is `serde`, the value type a tool call's arguments arrive as, and `uuid` for the id mint (**D493**) — a list that short is the whole reason it is a crate: a frontend that renders a transcript builds nothing else. P25 put the teammate surface here too: `team.rs` (the frames two agents exchange, and the `TeamView`/`MemberView` projection a frontend renders a team from), `PartBody::Peer` — a teammate's words, drawn *and* sent as §5.3's envelope while staying outside `Part::as_text` (**D495**) — and `PermissionMode` with `Command::SetPermissionMode` (**D496**). A provider-run tool call is a third display-only part, `PartBody::ServerTool` — drawn by every frontend, sent by no wire, because a Tool part is what encoders replay as a function call the roster never advertised (D489). Reasoning arrives as two parts, and the split is load-bearing: `PartBody::Reasoning` is the opaque provider state a `store: false` turn hands back on its next request, while `PartBody::ReasoningText` is thinking a person can read — **display-only**, drawn by every frontend and sent by no wire, kept out of `Part::as_text` so it can never title a checkpoint or answer a copy command, counted as nothing by the context meter, and carried by no summary. Upstream opencode fuses the two into one part and replays it into the request (`session/message-v2.ts:362-376`); ganja splits them, which is what makes "display-only" a thing the type system can state. Its tag keeps the `reasoning` prefix that `REASONING_TAG` makes a forward-compatibility contract of, so a build too old to decode one still leaves storage's marker in its place rather than dropping the row without a word. D529 added one field in `skills`' exact idiom: `session_mentions` on `SendPrompt` and `Steer` — the `@` tokens that named a teammate or a live session, names not resolutions (the engine resolves where the authority lives), still present in `text`, `#[serde(default, skip_serializing_if)]` so a prompt carrying none is byte-for-byte yesterday's bytes.

**`ganja-permission`** — a call becomes one or more patterns; the **last matching rule wins**, and **every** pattern must be allowed for the call to run unasked. Rules layer builtin defaults < the agent's < the config's < the answers a person stored. Shell "always" answers remember the *kind* of command via upstream's arity table. A subagent inherits the refusals and never the allows: nobody is watching its turn. `project.rs` rides along — which worktree this is decides where the answers are stored and what counts as outside it — and the crate's own docs own that the name is a small lie about that. D531 widened the crate's API by exactly one entry point and no policy: `gate_with_default` takes the caller's default-for-unmatched (`unmatched: Option<Decision>`; `None` is the static ladder exactly as today) and consults it only at the arm where no stored answer, no config rule and no agent rule matched, ahead of the static `ASK_BY_DEFAULT`/allow lists — `gate()` delegates with `None`, so the precedence ladder keeps its single in-crate spelling and the equivalence is pinned by test. The crate stays policy-source-free: the engine computes the default from state this crate deliberately cannot see — since **D543** a live read of whether this session's own team holds anybody, beside the resolved `teamless_send` — and hands in only the conclusion; an explicit rule, a stored "always" answer and a deny all still outrank whatever is handed in.

**`ganja-team`** — Claude Code's teams directory: the member records and the file-backed mailboxes teammates are addressed through (**D497**, P25; upstream opencode has no teams, no teammates and no second agent to address, so there is no TypeScript to port and every sentence in it is ganja's own). It is a crate because the documents are **somebody else's format** — a real `claude` process may be sharing the very directory it writes into — which makes two things interop contracts rather than implementation details: the bytes of a document, and the protocol by which a writer holds an inbox. Both are served by a `#[serde(flatten)]` passthrough over an `IndexMap`, so an unknown key survives a rewrite *in the position it arrived in* — the exact opposite of `ganja-protocol`'s declare-and-refuse posture, which is why the two cannot be one crate. Locking is `proper-lockfile`'s protocol as that library defines it: a lock **directory**, never a file, broken on mtime alone past ten seconds, no pid liveness. What it does not know is where ganja keeps its homes, what a session is, or what a permission decides — the teams root arrives as a `TeamsRoot` value the way `skill::Roots` arrives in `ganja-tool`, and its internal dependency list is exactly `ganja-protocol`, asserted closed from the crate's first commit. It is deliberately **synchronous**: a mailbox write is a sub-second read-modify-write on a small file, and whoever calls it from inside a turn wraps it in `spawn_blocking`. A frontend that merely *renders* a team needs no dependency on it at all — that is what `ganja-protocol`'s own `TeamView`/`MemberView` projection is for.

**`ganja-tool`** — `Tool` trait + `Registry::with_builtins()`: the file tools (read, edit, write, glob, grep), `bash`, `todowrite`, `webfetch`, `websearch`, `skill`, `question`, and the resident `tool_search` and `list_sessions`, plus `task` and the two plan doors the engine registers once it knows which agents this session may spawn. Schemas are generated from the argument structs, `FileTimes` enforces read-before-write, glob and grep run in-process on the ripgrep crates, and `write` and `edit` reach the disk through a directory descriptor (`anchor.rs`) rather than twice through a path, so a link swapped in after the permission dialog has nothing to redirect. Three answers are hoisted down here because this is the lowest crate that needs them: `socket.rs`'s session-socket scheme with `prepare_directory` (**D505**, **D509**), and `registry.rs`'s registration record and name grammar (**D527**). Its internal dependency list is asserted closed at exactly `ganja-permission ` — the engine is deliberately outside its graph, so a tool that seems to need the loop is a tool that needs another value in its `ToolCtx`. Decisions it owns: **D477**, **D492**, **D498**, **D505**, **D509**, **D527**, **D528**, **D530**, **D533**, **D535**, **D543** (its description half; stated in full in `crates/ganja-core/AGENTS.md`), each stated in full in `crates/ganja-tool/AGENTS.md`.

**`ganja-provider`** — talking to a model vendor: the wires, the credentials they present, and the table that sizes and prices what they serve. A wire turns a `ChatRequest` into HTTP and an HTTP response back into a stream of `ProviderEvent`s; it knows nothing about sessions, tools or storage, and with the engine outside its dependency graph that is the compiler's rule rather than a convention. Anthropic Messages, OpenAI's Responses API, the chat-completions wire grok and Copilot ride, the Connect wire cursor's agent backend speaks, the fake provider, and `compat` — not another wire but the three real ones reached at an endpoint a config named, under the id it named. The cursor wire has no upstream TypeScript to port, so its spec is a recorded live probe: Connect, not bare gRPC — enveloped streams whose failures arrive as in-body EndStream frames — with the framing hand-written over the same reqwest/rustls stack, the messages riding `buffa` (pure-Rust protobuf, license-matched), and ganja's own `.proto` checked in beside its generated module under a drift test. Its Run RPC is a duplex: the request body is held open because the server generates by *asking* — a context exec whose answer is the one system-prompt channel cursor honors, and kv blob get/set served from a per-turn map — and a tool exec (shell, read, write, …) is refused on the descriptor's own throw-and-close pair so the server reads a failed tool and the turn survives (**D486**), while a kv kind outside get/set still fails the turn naming it, never hangs it; the prost/tonic fence that once reserved a separate crate for a gRPC stack retired with the reason it existed. P19 added the gateways: `openrouter` rides the Responses machinery at the vendor's own base under a plain key, every OpenAI-shaped body assumption re-derived against the vendor's reference — the API is stateless, so nothing is replayed, nothing sealed is recorded and no summary is asked for, each drop a refusal to guess recorded in the module doc — three sends now stand beside the drops: `reasoning.effort` off the /effort roster, `tool_choice: "auto"` on a roster-bearing request, and the opt-in `openrouter:*` server-tool rows (D489), whose calls come back as the display-only `ServerTool` part; `opencode` and `opencode-go` (the zen gateway's two tiers, **D488**) are one module registered twice over one key, dispatching per model to whichever of the three existing wires the catalog row's npm hint names — choosing the wire chooses the auth header, which is what the gateway's `x-api-key`-only Messages path requires — with the Messages base stripped of one `/v1` because that wire re-adds it. Everything filed under `openai` speaks Responses and asks it to seal the model's reasoning, which the transcript carries and the next request hands back; the credential picks the *backend* and what the request carries beside the bearer. Two failure channels, never a completed turn; retry only before the first byte — with one bounded exception, D475: an in-body failure that arrived before any content event is retried up to three times, since nothing rendered that a replay could duplicate; credential-travel bounds (no redirects, https-or-loopback) live here. **Auth and the catalog fold in rather than standing alone**: the auth→provider edge is one function (`reachable_in_the_clear`, the OpenAI login's redirect check) against some forty provider→auth references reaching per-provider submodule internals, and the catalog names providers by the ids `auth::storage_key` maps to disk — a boundary between any two of them would carry no invariant anyone would gate. What did *not* move is selection: `select` reads a `Config`, so it stayed in the engine over a facade that re-exports the wires. **What this build tells each host it is** is now decided per host rather than inherited once for all of them (**D521**): three hosts carry ganja's own name, the rest carry upstream's on purpose, and the difference is a measurement rather than an argument — every move landed only after a live run against that host recorded what the host did with it, and the one host left borrowed is left borrowed because its failure mode is the one nobody can measure safely.

The rule that keeps those two columns apart is a test rather than a comment — `auth::device`'s divergence pin asserts host by host that the moved three equal `GANJA_USER_AGENT` and the borrowed one does not, so a later "simplification" of two near-identical constants into one reddens instead of quietly sending ganja's name to the one host that must not receive it. Identity fields on a single host **move together or not at all**: `originator`/`referrer` and `User-Agent` are one decision, because a request naming itself one thing in a header and another in a query manufactures exactly the mismatched-telemetry signature this is trying not to look like. Impersonating the vendor's own client — sending `codex_cli_rs` on the codex backend — was considered and **refused**, and is recorded as closed rather than unconsidered: it would buy feature parity by claiming to *be* OpenAI's Codex CLI, defeat the gating mechanism by design, corrupt that vendor's telemetry about its own product, and pin ganja to tracking every Codex CLI release, since a stale version string is itself an anomaly. Four deviations were ratified while this landed: the per-host `XAI_USER_AGENT` consolidation that made grok's three call sites one edit; a plan-inventory grep that could not see pins embedded in `format!` or `.to_owned()` pairs, which is why every site list was re-derived quote-free; a module-doc header count that would have cited `codex.ts:405-408` for four headers that line range does not set — a false citation being worse than a stale number; and grok's own literal pin held to the **name** rather than the versioned string, so an ordinary release bump cannot redden a test about identity.

**`ganja-storage`** — where sessions live between runs, and the working-tree snapshots `/undo`/`/rewind` walk. Born as two modules inside `ganja-core` (`storage.rs`, `snapshot.rs`) and split into a leaf of their own in **D540** (`.omc/plans/2026-08-28-teammate-seam-crate-split.md`, W3) — the `634d8dd` provider-split procedure, applied a second time on the other side of the engine. One SQLite database per project, `session`/`message`/`part` with opaque JSON `data` columns, upstream's migration journal and pragma set, writes serialized through a dedicated thread so their order is structural while reads take a second connection under WAL; a `storage/` tree from a build before this one converts on first open and is renamed rather than deleted, unless its ids predate UUIDv7 (**D493**), in which case the whole tree — or the database with its write-ahead log — is set aside as `*.preuuid-<millis>` under a flock'd `sessions.db.quarantine.lock` and a fresh store takes the name. Beside it, a separate git directory under the data home takes snapshots of the working tree with no commits of its own — `write-tree` names a tree and that hash is the snapshot — for `/undo` and `/rewind` to check files back out of. Its own internal dependency list is closed at exactly the two bottom crates, `ganja-permission ganja-protocol `, the same allowlist form every other member's boundary takes: a session store needs to know which worktree it is anchored on and what a stored record decodes to, and nothing else — `rusqlite` moved here whole, and it is the only member whose *normal* manifest names it. `ganja-core` re-exports both modules under the names they always had — `ganja_core::storage`, `ganja_core::snapshot`, `SessionId`, `SessionInfo`, `Storage`, `StorageError`, `RevertState`, `Snapshots` — so no caller outside this crate had to change a path.

**`ganja-core`** — the engine. No terminal dependency (CI-enforced), so it is testable headless and can later be served over a socket. It re-exports the crates beneath it under the module names they always had — `ganja_core::protocol`, `::permission`, `::project`, `::tool`, `::watch`, `::auth`, `::catalog`, and since P25 `::team` — so each split cost no caller a rewrite; new code that wants one of them alone should depend on it directly, as `ganja-cli` does for `auth login`. `ganja_core::provider` is the one facade that is not a bare re-export: the wires left and the half that reads a `Config` stayed, over a glob of what moved.

- `engine.rs` — commands in, an ordered event stream out. Delivery is **per-subscriber**: every subscriber has a bounded queue of its own — a lossless subscriber (`subscribe()`) makes the publisher wait, so backpressure lands on the turn task and never on the render loop, while a droppable one (`subscribe_droppable()`) is evicted with an observable error rather than waited for. The first subscriber inherits everything buffered since the engine was born; later ones join from registration. Every event names its session, filled from the engine's one current-session slot (minted at construction, adopted by the first prompt's row, replaced by resume, re-minted by `NewSession`); a subagent's crossing permission dialogs carry the parent's. **Root turns stay serial** — `TurnSlot`, `Busy`, "one turn at a time" all still hold — but *within* a running turn, consecutive `task` calls in one assistant step now fan out concurrently (capped by `agents.concurrency`, default four) and fan back in on completion order while parts keep call order (**D462**); the pending-reply registry (`session.rs`) lets several children hold open permission or question dialogs at once, queued rather than collided, each answered by id. `Engine::settle` polls the turn slot so a headless caller (`ganja run`) can wait for a turn's tail — its `Stop` hook included — before the process exits; `Engine::jobs()`/`shutdown_jobs()` own the background-job registry `job.rs` describes, torn down on the same exit path as `shutdown_mcp`/`shutdown_lsp`. The event stream is complete — a frontend that applies every event holds exactly what the next `ChatRequest` will carry. Two read accessors serve P14's surfaces from the same estimator compaction trusts: `context_estimate()` (tokens against the catalog window, what the status bar's meter polls) and `context_breakdown()` (the per-category split `/context` renders, computed at the request-assembly seams rather than re-derived by any frontend). Four narrow reload seams — `replace_hooks`, `replace_base_tools`, `replace_skill_roots`, `replace_environment` — exist for exactly one caller, the `/plugin` dialog's Reload (**D474**; the skill-roots seam joined in P23 so a reload swaps the `$` expansion's roots beside the rebuilt skill tool): each swaps state a turn clones at its start, so a running turn keeps what it began with and the next one reads the reload. **They take `&self`, over `std::sync::Mutex`** (D474 amended in P25/W7): a lead session hands its engine to a socket server and to its own loop at once, so `Engine` had to become shareable, and after the change **no `&mut self` method survives on it** — the frontend holds an `Arc<Engine>`. The rule that makes that safe is machine-checked rather than reviewed: no guard lives across an `await`, which clippy's `await_holding_lock` asserts at `-D warnings`.
- `session.rs` — the agent loop. Mark a step, ask the model, execute the tools it called, repeat until a request ends without tool calls. **Tool results are information, never control flow**: a refusal, an unknown tool, unparseable arguments or a failed tool all become error text the model reads next, and the loop continues. Only a cancel or a dead provider ends a turn early; there is no step cap. A step's calls resolve through four phases (`prepare`→`start`→`body`→`finish`) so a batch of concurrent `task` calls and an ordinary sequential call share one code path — only `body` ever leaves the turn's own thread. `crate::hook`'s nine events fire from five seams here: `PreToolUse`/`PostToolUse` bracket a call (a `PreToolUse` block, exit 2 or `permissionDecision: "deny"`, routes the same `fail_call` a denied rule does; `"allow"` skips the dialog and never overturns a stored deny, **D458**), `Notification` brackets a permission or question wait, `Stop` fires at the turn's tail before the slot releases, and `PreCompact` fires before compaction. `Turn.hooks` is inherited by `Turn::child`, so a subagent's own tool calls are gated too, and `subagent.rs` fires a child's own `SubagentStop` once its turn and its watcher both resolve. A prompt's or steer's `$name` invocations expand here as well, at the same seams mentions resolve at (**D491**): each name becomes the `skill` tool's own `<skill_content>` rendering — `skill::rendered`, shared and never copied, pinned by a byte-identity test — or its not-found sentence, off the roots `Engine::with_skill_roots` installed; a miss is information the model reads, never a dead turn, and no permission dialog or hook fires because the person typing the token is the consent.
- `hook.rs` — commands a config runs at those nine named moments (`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStop`, `SessionStart`, `SessionEnd`, `PreCompact`), spawned under the same POSIX shell `bash` uses with the event's JSON envelope on **standard input** — this module owns its own spawn because `ShellTool`'s hard-codes `Stdio::null()`. Every hook matching one event runs concurrently and is awaited under its own timeout; exit 0 passes and its stdout is read as the documented envelope or as plain text; exit 2 blocks where blocking means something (`HookEvent::blocking` is exactly `PreToolUse`/`UserPromptSubmit`); anything else — including a timeout kill — is a non-blocking failure reported through `tracing` and the returned `Outcome`, never through a new protocol event (**D459**). A hook runs with the **user's own authority** and crosses no permission dialog — the config file it came from is the trust boundary — and never fires for another hook, by construction rather than a guard. No upstream opencode counterpart at all (**D456**); the stdin envelope omits Claude's `transcript_path` because this build's transcripts are SQLite, not JSONL (**D457**).
- `job.rs` — background shell jobs: a `bash` call started with `run_in_background: true` returns immediately and keeps running under `JobRegistry`'s own root cancellation token, a child of nothing a turn owns, so a turn's cancel never kills a background job. `bash_output` drains whatever a job wrote since the caller's last poll (one cursor per job — this port's shape has exactly one caller per job) with an optional regex `filter`; `kill_shell` ends the whole process tree. No upstream counterpart (**D454**); the `timeout` argument the tool shares with the foreground path is silently unconsulted on this branch, by design — backgrounding exists precisely so a call can outlive the foreground default (**D455**). The status bar's `N bash running` segment polls `Engine::jobs()` on every tick.
- `teammate/` — with the teammate halves of `subagent.rs`, `session.rs` and `engine.rs`: agents that outlive the call that started them, and the wire between two ganja sessions. **D538** deepened the seam a wave ahead of the crate split that used it: `TeammateBackend::spawn` now returns `Arc<dyn Spawned>`, which owns launch, the bridge loop, liveness, the recent-calls ring and kill, so the registry no longer knows which *kind* of member it started. What stays here is the halves that govern every backend alike regardless of which crate spawns it — `identity.rs` (the sender-side resolver, refusing rather than guessing), `inbound.rs` (the receiver-side admission gate that decides what the model *hears* where permission decides what it *does*), `lead_inbox.rs`, `member.rs`, `postbox.rs`, `posture.rs`, `preamble.rs`, `receipts.rs` (the settlement receipts a held message answers with) and `runner.rs`, plus `teammate.rs` itself — the trait, the registry, `Spawned`, `Lent`, and `InProcess`, the one adapter an engine can build entirely out of its own provider, tool set and store. **D539** then moved everything that needs a tmux server, a shell to split into, or somebody else's binary on `PATH` — `tmux.rs`, `pane.rs`, `claude.rs`, `shim.rs` (with `shim/records.rs`), `shim_tui.rs`, `codex.rs`, `grok.rs`, `agy.rs`, `reaper.rs` and `readback.rs` — into `crates/ganja-teammate-local`, a crate *above* this one the way a frontend is: `Backends` is assembled outside the engine by whichever frontend is running and handed to `Engine::with_teammates`, chosen by name and refused by name rather than silently fallen back to — `in-process` here, the default `ganja` and `claude` in tmux panes, and the `codex`, `grok` and `agy` shims in the crate above, over a registry whose cancellation token is a child of nothing a turn holds, so cancelling a turn never ends a teammate. Beside them: the file-backed mailboxes `ganja-team` owns. Nothing here is ported from upstream opencode, which has no teams and no second agent to address; the specification is Claude Code's own behavior, or a foreign CLI's, measured against its recording under `crates/ganja-teammate-local/tests/fixtures/*-posture-probe.txt` and `*-tui-probe.txt` (the identity probes, D521's, stay at `crates/ganja-core/tests/fixtures/{codex,grok}-identity-probe.txt` — a provider fact, not a teammate one) — and wherever a probe contradicted a plan's pre-probe prose, the probe won. Decisions it owns: **D497**, **D500**–**D515**, **D520**, **D523**–**D535**, **D538**, **D539**, **D541**, **D543**, and the execution-time deviations these landings recorded in ledgers of their own — P27's seven, the closing cross-session landing's four, and the seam-and-split's own twelve, each ledger numbering from **Dv-1**, so a bare `Dv-3` is ambiguous until you say which. P27's own ledger is stated in full in `crates/ganja-teammate-local/AGENTS.md`, where D507–D512, D515 and D541 now live; the closing cross-session landing's ledger is stated in full, the same way, in `crates/ganja-core/AGENTS.md`; the seam-and-split's own ledger is stated in `.omc/plans/2026-08-28-teammate-seam-crate-split.md`, since it is a plan document's own execution record rather than a landed decision this file summarizes.
- `provider.rs` — half a module, and the half that reads a `Config`: `select`'s four-tier chain, `Selection`, `selectable`, the `Wire`/`openai_provider` dispatch that picks a backend by *kind* of credential, and the config→wire translation. The wires themselves are `ganja-provider`'s, globbed in so every path a caller already writes still resolves.
- `mcp.rs` — config-named MCP servers, dialled concurrently in the background at startup; their tools join the registry as `mcp__<server>__<tool>`, every one of them asking by default — the registry name is the one permissions, hooks and transcripts key on; a wire whose vendor refuses that spelling advertises a deterministic alias and translates the model's calls back (`provider/toolname.rs`). The original "dialled once, never reconnected" posture retired (**D463**): `Servers::reconnect` is the `/mcp` dialog's manual door for a server the dialog shows as `Failed`; `Servers::retry_once` is a bounded, spawned-and-never-awaited automatic redial — exactly one per server per session — for one whose very first dial never succeeded, run off the existing `refresh_mcp` once-per-turn-start seam; either door bumps `Servers::generation` so only the *next* turn sees revived tools. A tool result over a server's `output_limit` (bytes, default `MAX_CHARS`) is clamped through `truncate::clamp_bytes`, the same spill-file posture every other one-shot tool here uses (**D464**). A remote entry may add `oauth: {}` to discover its own authorization server (RFC 8414), register a client (RFC 7591, falling back to a fixed public id when the server names no registration endpoint), and run the existing PKCE/loopback browser login, storing the result under a reserved `mcp:<server>` credential-store key; the dial sends the bearer proactively and retries once, refreshed, on a `401` that carries `WWW-Authenticate` (**D466**, `ganja-provider/src/auth/mcp_oauth.rs`). No upstream counterpart for any of the three — opencode dials once, and the `oauth` key it refused by name at the old pin is silently ignored since v1.18.22's ignore-unknown posture (#41312): unimplemented either way. Past the config's `tool_defer_threshold`, what those servers lend is *advertised* selectively (**D492**, minted at `session.rs`'s filter): whole servers' schemas defer largest-first through `ganja-tool`'s one `retain_advertised` filter — the registry, the permission/hook/transcript keys and `/mcp`'s counts stay whole — a per-step block beside the reminders names the deferred, the resident `tool_search` activates a schema for the session (advertised from the very next step), a direct call executes and activates on either outcome, and activations are flushed to the root session row at each root-side call's `finish` (a child's arrive at the parent's `task`-call fan-in), re-seeded on every resume from the row unioned with the full transcript's `mcp__*` call names, and reset by `NewSession`.
- `lsp/` — language servers, opt-in by config and spawned lazily by the first touch of a file they claim. Diagnostics — errors only, pushed and pulled, merged and deduped — are appended to `edit`/`write` results at one seam in `session.rs`; no LSP failure may fail a tool call or a turn.
- `plugin.rs` — Claude Code's `.claude-plugin` plugin and marketplace shapes, verbatim (**D472**, `claude-plugin-spec`; upstream opencode has no plugin system at all), over an install store at `<config home>/plugins/` whose only doors are the explicitly typed `ganja plugin` subcommands and the `/plugin` dialog — install is the consent, because a plugin's hooks and MCP servers run with the user's own authority. Foreign files are read tolerantly (Claude ignores unknown manifest keys, so this parser does too) but every name is refused at parse if it could escape the store, and a marketplace add stages, validates, then moves — no failure leaves half an add behind. At config load each enabled plugin becomes a **config contributor**, merged per surface at exactly one point in `Config::load_with` rather than as a fourth tier through `Config::merge` (**D473**, `plugin-component-merge`): hooks *append* beside config-declared groups, MCP servers arrive namespaced `plugin:<name>:<server>` and ask by default, `skills/` concatenates onto the roots, `commands/*.md` join the `command` table namespaced `<plugin>:<name>` — Claude's own spelling for a plugin command — read by the very loader a project's own `.ganja/commands` goes through rather than a second parser, and agents and LSP entries merge per key with the explicit config winning and the collision reported by name. Six surfaces, and the sixth (commands) closed the set in P22. One collector walks a plugin's components for the listing and the load path both, which is what keeps `ganja plugin list`, the `/plugin` dialog and what a session actually serves one answer.
- `agent.rs` / `instruction.rs` / `command.rs` — who a turn runs as (build, plan, general, explore, plus whatever the config adds), the system prompt it runs under (a base prompt per model family, the `<env>` block, the `AGENTS.md` family — including, since P15, the nested files a touched subtree earns lazily (**D480**) and the opt-in memory section (**D478**)), and the slash commands it can run. A command's template expands the way upstream's does: `` !`cmd` `` runs through the passthrough's spawn at the project root and substitutes its output, and `@file` attaches the way a composer mention would. The base prompts themselves now speak in ganja's own name (**D522**, 2026-08-25): `anthropic.txt`, `gpt.txt`, `default.txt` and `initialize.txt` are no longer byte-verbatim upstream but derived from it, substituting the agent's own name (`OpenCode`/`opencode` → `Ganja Code`), the repository and docs URLs a user is handed for feedback and documentation (`anomalyco/opencode` and `opencode.ai` → `https://github.com/zchee/ganja-code`) and the config file `/init` tells a person to look for (`opencode.json` → `ganja.jsonc`) — and touching nothing else. It landed now because **D521** had just moved *wire* identity per host: with what this build tells a vendor it is decided honestly, the prompt texts were the last place ganja still told anyone it was opencode, this time the person on the other side of the conversation. The three prompts that name upstream nowhere — `plan.txt`, `build-switch.txt` and `explore.txt` — stay byte-verbatim; the substitution classes are enumerated in `crates/ganja-core/src/prompt/AGENTS.md`, which is what keeps the other four diffable against upstream at all, and `THIRD_PARTY_NOTICES.md` moved from claiming verbatim copies to the derived-with-attribution wording in the same commit, because a notice that calls a file verbatim is false the moment it is not.
- `config.rs` — `ganja.toml` across three tiers, under the environment and the flags. Unknown top-level keys are refused by name — a deliberate divergence since v1.18.22, where upstream moved to ignoring them (#41312): an ignored setting is one its author still believes applies. `hooks`, keyed by event name, is Claude's own `{matcher, hooks: [{type: "command", command, timeout}]}` shape kept verbatim for migration familiarity — somebody who knows Claude's block knows this one — though the *paste* that shape used to allow left with the format and was traded rather than lost (**D537**), refused unknown by event name and by handler `type` alike; `agents.concurrency` (default four, refused at zero) caps how many `task` calls one assistant step runs at once — its own settings object beside `agent`'s per-name map, not a key inside it, since a `concurrency` key living in that `BTreeMap<String, AgentConfig>` would collide with an agent actually named that (**D462**); an MCP entry's `output_limit` (bytes, not the catalog's tokens) and a remote entry's `oauth: {}` marker are the two other P13 additions, all curated and refused by name at load like everything else here. P15's `memory` (bool, absent = off) is the opt-in for the per-project auto-memory section (**D478**); P16's statusline roster gained the `rate` element (**D484**), and on 2026-08-26 the `held` element (bead 2zl) — D524's `N held` segment as a named element a configured roster places and orders like any other, appear-only-while-nonzero, the dialogs-side piggyback retired, the absent-config bar unchanged; P17's `effort` (string, absent = none) seeds a *fresh* session's catalog effort through `Engine::seed_effort` — a default, not an override, so a resumed row's own effort wins, and a name the selected model does not serve clears with a log line at adoption rather than refusing the config at load. P20's `openrouter` table (`server_tools`, a list validated against the vendor's documented roster and refused unknown by name) is the opt-in for that gateway's server-run tools, which bill per call (D489). P24's `tool_defer_threshold` (unsigned integer, absent = 32) is the advertised `mcp__*` schema budget (**D492**): past it whole servers defer largest-first, `0` defers every server and a huge value disables deferral — counted in tools, the unit `/mcp` itself lists, and top-level because a key inside the `mcp` table would collide with a server named `defer_threshold` (the D462 lesson). Size is not coldness: the deferred giant may be the main server — its tools return to the roster the moment they are touched, and raising this key is the one-line off switch. P27's `teammates` table holds `shim_turn_timeout` (seconds, absent = the per-CLI default, refused at zero): the per-turn deadline a **headless** foreign-CLI teammate runs under, plural for `agents`' reason and a table of its own because it is about how this session *runs* the teammates it spawns rather than about what they are (**D509**). Since P28 (**D512**) it governs that headless machinery only, which no spawn door in this build reaches — a pane-mode shim has no per-turn deadline — so the key is kept curated (a file already carrying it must still load) and is read by nothing a spawn reaches. Its second key, `teammates.shell` (**D520**, 2026-08-24), names the idle shell every pane teammate is spawned into as a command line (`"/bin/zsh -f"`), shlex-split at load and refused empty; the pane door appends `-s` to a lone program so the two-word rule tmux's own `$SHELL -c` detour makes load-bearing survives, and the default stays `/bin/sh -s` for the measured reason — a shell somebody names runs its own startup files, and what they export enters the pane past D502's enumeration, which the key's doc says is the person's choice. Resolved at assembly into the `PaneShell` the frontend hands each pane backend it builds (`ganja_teammate_local::backends`, called from `crates/ganja-tui/src/lib.rs`), so no backend names a config type and the registry holds none of it (**D538**). Its third key, `teammates.pane_share` (2026-08-25), is the percentage of the window width the teammates' column takes when the first teammate opens it — 65 by default, the lead keeping the rest; tmux's `-l` sizes the new pane, which is why the number is the teammates' — refused at load outside 1–99, resolved the same way into the `PaneShare` those backends are built with, and read at spawn into `Placement::Beside`. The admission gate's two keys (**D523**, 2026-08-25) are this file's one surface whose project tier is not later-wins: `cross_session_inbound` merges by severity there — a checkout may tighten `accept < hold < refuse`, never loosen — and `dialog_expiry`, the review window a parity hold's timer runs on (D524), is refused from a project file outright, naming the key and the file; the rest of the gate is the `teammate/inbound.rs` bullet's, in `crates/ganja-core/AGENTS.md`, and neither key is a surface a plugin can contribute. The sender side's one key sits beside them (**D531**, 2026-08-27): top-level `teamless_send: "unasked" | "ask"`, absent = `unasked`, refused unknown by name — in a session that holds a team it has no effect at all (in-team D498 is byte-untouched), and in a teamless one `ask` puts an ordinary storable permission dialog in front of each `send_message`. It said *would* for two days: **D542** (2026-08-29) found no shipped session teamless in this key's sense at all, the assembly arm that installed a solo postbox having been deleted as structurally unreachable, and **D543** (2026-08-30, bead `ganja-code-3tng`, stated in full in `crates/ganja-core/AGENTS.md`) made the key live by deriving the state instead of latching it — a session is teamless when its own registry holds no members, which every session that has spawned no teammate is, so the same key now acts on the shipped path and a teammate joining reverts it to D498's ladder; its project tier merges by the same tighten-only severity mechanism as `cross_session_inbound`'s (`unasked < ask` — a checkout may demand more sender-side oversight, never less), the two keys' docs cross-reference each other as the two independent knobs on the two ends of one wire, and no plugin contributes either. P14 added the curated `tui` table — `notifications` (bool or event filter), `notification_method` (`osc9`/`bel`), and `statusline` with its named-element roster, an unknown element name refused at load by name — the one config surface that exists purely for the terminal frontend, still parsed and refused here because this file is where every key is either curated or refused. **The format itself is TOML** (**D536**, 2026-08-28), one name — `ganja.toml` — in every tier, and a **clean cut** rather than a deprecation window: a discovered `ganja.jsonc` or `ganja.json` is a `ConfigError` naming that path and `ganja config migrate`, and the legacy probe runs **first**, whether or not a `ganja.toml` is sitting beside it, because reading the new file and saying nothing about the old one would be this bullet's own ignored-setting failure wearing a different hat — whoever left a legacy file in a directory believes it is doing something, and the launch that would have skipped it is the only honest moment to say otherwise. The refusal is decided by **extension** rather than by whole file name, since discovery is not the only way a path arrives — `GANJA_CONFIG` and `--config` name one that can be anything, and a `~/mine.jsonc` deserves the sentence a discovered `ganja.jsonc` gets — while an unknown extension, or none, is read as TOML, the direction the default has to fall now that there is one format. The JSONC dialect survives in exactly one module, `config::legacy`, **moved rather than rewritten** so a file that loaded before the change loads the same way there, with two callers and no third: `ganja config migrate`, and `import-opencode`, which reads *upstream's* files — still JSONC, somebody else's format, migrating nowhere, which is why `parse_options` stays public and the dialect it describes has to keep agreeing with what upstream writes. `legacy::read` runs the loader's own seven post-decode refusals through the same private `checked` the TOML path uses, because a source this build would decline at launch must be declined at the read rather than translated cleanly into a `ganja.toml` whose first launch refuses it. **Document order is the load-bearing property of the whole change**, and it is pinned at three heights rather than trusted at one: at the loader, where TOML must reach `PermissionConfig`'s Visitor in the order the file spelled its keys (headers, dotted keys and interleaved non-contiguous tables alike); at both writers that render a whole config from a decoded value — `migrate` and `import-opencode` — where everything under a `permission` key is written as an **inline** table, because a TOML table's key-values must all print before the first sub-table header that re-enters it, so a `{bash, edit}` map spelled as a header would reach the loader as `edit, bash`; and at the permission engine, whose last-match-wins evaluation is the reason any of it matters. A silent inversion there — an `ask` rule quietly losing to an earlier `allow` — is the worst failure this change could have produced and nothing would have shown it, so it got the first test written and the mechanism was chosen by that test rather than assumed. `migrate` compares the two decoded configs for equality before writing anything, which is the belt to that suspenders. The deliberate cost is recorded beside the decision: the `.claude/settings.json` **paste** compatibility the `hooks` shape used to allow cannot survive a format change, and was **traded, not lost** — `ganja config import-claude-hooks` (**D537**, 2026-08-28) reads a settings file and maps its hooks block onto a `ganja.toml`, appending each group after whatever the target already holds for that event, which is the config system's own hooks semantics, through the same format-preserving editor (`toml_edit`) `mcp add` edits with, so the target's comments and key order survive. Every event, handler `type` and field it could not carry is **reported by name** — an event this build does not fire, a handler that is not a command, a group the loader would refuse — and every other key of the settings file is reported unread; a matcher is judged by the *same regex engine the loader judges it with*, which is the only way the two answers cannot disagree, and every refusal runs before a byte is written, with `--dry-run` printing the table and writing nothing. A command that names what it skipped is worth more than a paste that silently drops what this build has no `hooks` roster for, which is the argument `import-opencode` has made about upstream's keys since P7 and the reason the trade was ruled a fair one.

CI asserts both directions of that promise (**D538**, **D539**): `ganja-core`'s own internal allowlist is unchanged by this crate's existence, and the `depgate.toml` deny rule that is this split's whole point — **`ganja-serve` never links it** — proves the closure `ganja serve` ships can never spawn a pane or a foreign CLI on somebody else's machine, which is what a cloud worker built on that same closure will need to be provably true of it too. **`ganja-tui`** — every pixel, no engine logic. It links `ganja-protocol` for the types it renders, `ganja-permission` for the stored rules it loads and hands to the engine, `ganja-tool` for the one thing it runs in-process, the `@` menu's glob walk, and `ganja-teammate-local` for the five external teammate backends it assembles into a `Backends` at spawn time; CI asserts it never grows an `axum`. One `tokio::select!` owns all mutable UI state and `App::handle` is the only mutator, which is what makes components testable without a terminal. The transcript pane draws Claude Code's own grammar, taken from a screenshot (**D487**) — `>` on a prompt, `●` on a reply block and on every tool call, `⎿` on what a call answered, `∴` on thinking — over themes that are loadable data, a composer carrying history, mentions, steering and clipboard images, the Ctrl+T inspector, and the dialogs behind `/mcp`, `/plugin`, `/team`, `/context`, `/usage`, `/rewind` and `/held`. Decisions it owns: **D111**, **D445**–**D447**, **D449**–**D453**, **D465**, **D467**–**D471**, **D474**, **D485**, **D487**, **D491**, **D495**, **D503**–**D505**, **D516**–**D519**, **D527**, **D529**, **D530**, **D532**, **D535**, **D542**, each stated in full in `crates/ganja-tui/AGENTS.md`.

**`ganja-serve`** — the engine over a socket: the legacy `/session/…` REST surface and a `GET /event` SSE stream, driving the same `Engine` the TUI does and inventing no state of its own — `GET /permission` is the one derived view, kept by a lossless subscriber that only moves map entries. Three postures are pinned by its tests: a non-loopback bind with no password is refused at startup (a deliberate divergence from upstream's warn-and-serve), the launch directory is the only directory served (anything else is `400`, never a silent answer about the wrong worktree), and no query string ever reaches a log line, because `?auth_token=` is a credential in a URL. The SSE stream opens with a `connected` frame, heartbeats every ten seconds, and ends an evicted subscriber with an observable `evicted` frame rather than a silent close; `EngineError` maps `SessionNotFound`→404 and `Busy`→409, with unparseable payloads at 400. P25 gave it a second transport (**D505**, minted here): a **Unix socket per interactive non-member session** at `/tmp/ganja-<uid>/<8+ hex>.sock`, `0600`, in a directory the bind refuses unless it is ours at `0700`, with a peer-uid check on every accepted connection. That clause read *per lead session* until 2026-08-27 and was never true of the landed tree — the gate the frontend hands its binder through was "locates a config home and is not a pane member" from the day D505 shipped — until **D542** (2026-08-29) folded it to membership alone — so a session leading nobody at all binds, registers and answers here; **corrected as an inaccuracy about this build**, not amended by anything. It takes no password — the filesystem already said who may connect — and since **D534** it serves **exactly four routes**: `GET /global/health`, `GET /team`, `POST /team/{name}/message` where the name must be the lead, and `POST /peer/receipt`, another session's settlement of a held message this one sent it. The fourth is the deliberate edit this table's own doc demands a name and a reason for, and it keeps the rule the table holds — **no write API without a credential** — because a route is a write API when posting to it changes what the session will do next, and this one does not: its whole effect is to settle one entry in a volatile in-memory map of ids this session itself minted and posted, nothing reaches disk, no turn is enqueued, no permission state moves, no mailbox is written, and the only thing a poster supplies is one of three enum values — every word the model reads about it is ganja's own rendering. The id is the whole capability and the route hands none out: an entry exists only because this session minted a v7 UUID, posted it to exactly one address and was told synchronously that the message is being held there, so a process that can name one either is that address or was told by it. The answer is identical admitted or dropped, for the same reason the message route already gives. Every session-mutating route and every other read of the session is TCP's alone and answers `404` there, because same-uid is not trusted: `ganja-permission`'s whole premise is that code this user runs — an MCP server, a hook, the model's `bash` — is not the user, and a credential-less socket serving the write API would hand every one of them a prompt into every session on the machine. Both route tables share one `guard` middleware, and a route added to the socket later is a deliberate edit named in `routes::socket_routes`' doc. The *scheme* it binds under is `ganja_tool::socket`'s, re-exported; what lives here is the binder's half — the name walk over a session's candidates, the flock'd `.lock` sibling that says a name is live (never removed, so a full-backlog listener is not mistaken for a dead one), and reclaiming a stale socket only under that lock.

**`ganja-client`** — the other end of `ganja-serve`'s wire, and nothing else: the typed routes and the SSE reader that `run --attach` drives. Its internal dependency list is exactly `ganja-protocol` (CI-gated) — a client that linked the engine would be a second frontend rather than a consumer of the first one's socket. The server's frame vocabulary (`connected`, `heartbeat`, `evicted`, and the event payload) is declared on this side and pinned against a real server; a frame or field outside the declaration is refused readably as version skew, never guessed at, and the credential comes from `GANJA_SERVER_PASSWORD`/`GANJA_SERVER_USERNAME` through serve's own resolver so the two ends cannot disagree about which variable means what. Since P25 it speaks **two address forms over one wire** (**D505**): a TCP base as before, and a socket path — `reqwest`'s own `unix_socket`, so no new dependency and no second HTTP stack, at the cost of one rule the type carries, that a `Client` routed at a socket is routed at *that* socket and is never shared across paths. `ganja sessions --live` health-checks through this form, which is why the crate's internal list is still exactly `ganja-protocol `.

**`ganja-cli`** — clap; no subcommand starts the TUI, one of them — `run` — takes a whole turn without it, driving the same engine headless and writing either readable lines or one JSON object per event (or, under `--attach`, the same account of a turn taken on a running `ganja serve`), and another — `serve` — puts the same engine behind HTTP and SSE until a signal ends it. It is also where the **binder** lives (**D505**): the binary is the only member that links both the terminal frontend and the server, so it is the only one that can hand the TUI a way to bind a socket without `ganja-tui` naming `ganja-serve`. The TUI decides *when* one is asked for — since **D542** exactly when the session is not a pane member, a member handing it back unused — and `ganja run` binds nothing at all, because a headless turn installs no teammates and never enters that frontend. `sessions --live` is the reader at the other end of the same scheme, and it unlinks under the name's own lock or not at all — and since D527 it also *names* what it lists: each row leads with the record's self-asserted name (typed case preserved, control characters scrubbed), and the GC under the claimed lock removes a stale socket's sibling record in the same window plus, in a separate pass, any orphaned record with no socket beside it — the name's lock claimed the same way, created if absent, no `.lock` ever removed. The binary is also where the trio's values enter: `--name` is vetted at the clap boundary by the registry's own grammar predicate so every refusal is the predicate's sentence, and the `Lister` the TUI's `@` menu consumes is implemented here (**D529** Axis 5, the D505 binder precedent) over the registry read, the liveness probe and a `ganja-client` health check — one live-vocabulary shared with `sessions --live` so the two listings cannot drift — constructed beside the binder under the same `--socket-dir` and handed in unconditionally, the TUI gating its use. The crate's tests carry the NameLock↔probe agreement pin (a name held by a real `NameLock` probes live and probes stale once dropped — this is the one crate linking both ends) and the two-process E2E: two real processes under one `--socket-dir`, a bare name resolved across it, the teamless sender's `@solo` identity and one-way note read back from the far inbox — over an engine that drill assembles through `with_solo_postbox` itself, since **D542** deleted the assembly arm that installed one, so what it pins is the engine seam rather than anything a shipped binary reaches, and the GC run against the survivor.

**`tmux`** — a tmux control-mode client and a second application of this repository's porting rule: `pandaemonium pkg/tmux`, an Apache-2.0 Go package by the same author as this workspace, is the behavioral specification, never source to translate. One persistent `tmux -C` subprocess speaks through piped stdio to an async `Client` built on `tokio::process`; beneath it, the sans-io `Parser` turns raw lines into guarded `%begin`/`%end`/`%error` response blocks and typed `%` notifications — the twenty known kinds, a synthesized `%protocol-error`, and a catch-all that preserves a newer tmux's unknown kind. It is consumed by **nothing** in this workspace and consumes nothing of ours, by the P26 user directive (2026-08-18), not by accident: CI checks both the consuming direction (its normal tree contains no `ganja-*` crate) and the producing direction (every other member's normal tree contains no `tmux`, over a member list derived at gate time). That makes it the deliberate exception to the root manifest's path-dependency convention. There is no `[workspace.dependencies]` entry for `tmux` because that entry would be the opt-in handle another crate used to depend on it, and no crate may opt in; the comment after `ganja-tui` in the root `Cargo.toml` explains the absence where a reader would look for the handle. The hard-fail-by-default real-tmux suite is evidence for keeping that cost: unlike Go's `RUN_REAL_TMUX_TESTS` opt-in, it ran at every port commit and found two cases the specification's own tests had never been forced to exercise. First, tmux's command lexer misparses a bare `%<digits>:word` token even though `%<digits>` alone is a valid pane id, so `pane_flow` single-quotes the compound argument the Go test renders bare. Second, a session-scoped subscription produces `-` in all three inapplicable window, window-index, and pane fields — observed live against tmux next-3.8 as `%subscription-changed live-test $0 - - - : x` — while Go validates those fields unconditionally because its real-tmux suite never asks for that scope; this port decodes the sentinels as `Option::None` and completes the roundtrip. Running real tmux on every commit is what surfaced both gaps, which an opt-in suite can structurally leave unseen.

### Testing Requirements

The four gates above, all green, before a phase is called done. Unit tests live beside the code as a **sibling file**: `foo.rs` declares `#[cfg(test)] #[path = "foo_tests.rs"] mod tests;` and the tests live in `foo_tests.rs` next to it (the flat layout the OpenAI Codex CLI's Rust workspace uses, adopted 2026-08-27; `#[path]` on a non-inline `mod` resolves against the declaring file's own directory, which is what keeps the pair adjacent). The module is still `tests`, so `use super::*` privacy, insta snapshot names and nextest filters are exactly what the old inline form gave; a declaration needing visibility keeps it on the declaration (`teammate.rs`'s `pub(crate) mod tests;`, whose doubles other modules' tests import), and `#[cfg(test)]` *support* modules that are not test suites (`binder.rs`/`lister.rs`'s `mod fake`) stay inline. Anything needing a real socket, a real filesystem layout, or process-wide environment mutation goes in a crate's `tests/`.

### Common Patterns

- Test names are sentences about behavior: `a_denied_edit_leaves_the_file_untouched`, `a_second_subscriber_sees_the_same_events_the_first_does`.
- A test that mutates process-wide state gets its **own test binary**. nextest already gives each test its own process, but the separation still holds the line under a plain `cargo test` (which runs a binary's tests on parallel threads) and keeps the intent legible.
- Anything touching stored state redirects `XDG_DATA_HOME` so it cannot read or write the real user's credentials, permissions or spilled output.

## Beads Workflow Integration

This project uses [beads_rust](https://github.com/Dicklesworthstone/beads_rust) (`br`/`bd`) for issue tracking. Issues are stored in `.beads/` and tracked in git.

### Essential Commands

```bash
# View ready issues (open, unblocked, not deferred)
br ready              # or: bd ready

# List and search
br list --status=open # All open issues
br show <id>          # Full issue details with dependencies
br search "keyword"   # Full-text search

# Create and update
br create --title="..." --description="..." --type=task --priority=2
br update <id> --status=in_progress
br close <id> --reason="Completed"
br close <id1> <id2>  # Close multiple issues at once

# Sync with git
br sync --flush-only  # Export DB to JSONL
br sync --status      # Check sync status
```

### Workflow Pattern

1. **Start**: Run `br ready` to find actionable work
2. **Claim**: Use `br update <id> --status=in_progress`
3. **Work**: Implement the task
4. **Complete**: Use `br close <id>`
5. **Sync**: Always run `br sync --flush-only` at session end

### Key Concepts

- **Dependencies**: Issues can block other issues. `br ready` shows only open, unblocked work.
- **Priority**: P0=critical, P1=high, P2=medium, P3=low, P4=backlog (use numbers 0-4, not words)
- **Types**: task, bug, feature, epic, chore, docs, question
- **Blocking**: `br dep add <issue> <depends-on>` to add dependencies

### Session Protocol

**Before ending any session, run this checklist:**

```bash
git status              # Check what changed
git add <files>         # Stage code changes
br sync --flush-only    # Export beads changes to JSONL
git commit --gpg-sign -F <msg-file>  # Commit everything: signed, message from a file
git push                # Push to remote
```

### Best Practices

- Check `br ready` at session start to find available work
- Update status as you work (in_progress → closed)
- Create new issues with `br create` when you discover tasks
- Use descriptive titles and set appropriate priority/type
- Always sync before ending session
