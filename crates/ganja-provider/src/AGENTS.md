# ganja-provider/src

## Purpose

Three modules and a private fourth. `provider/` is the wires; `auth` is where a credential comes from and how it is kept; `catalog` is what each model costs and how much it can hold. They arrived here together out of `ganja-core`, and the crate doc in `lib.rs` says why they are one crate rather than three.

## Key Files

| File | Description |
|------|-------------|
| `lib.rs` | Module list, the crate doc that records the one-crate ruling, and the two facade re-exports the moved code already wrote — `crate::protocol` for `ganja-protocol`, `crate::tool` for `ganja-tool`. |
| `provider.rs` | Sources of assistant text (see `provider/AGENTS.md` for the wires beneath it). The `Provider` trait, `ChatRequest`, `ProviderEvent`, `ProviderError`, the shared HTTP client, `check_base_url`/`reachable_in_the_clear`, the `events` pipeline every wire streams through, and the credential seam — `Presented` (a key or an access token, opaque and self-redacting), `CredentialSource` (where one comes from, consulted per request) and `Resolved` (what one request carries: the secret, plus the ChatGPT account id that travels beside it). Also `key_for`, `setting`, `configured_key` and `configured_headers`, the data-only half of what selection needs: the selection half itself is `ganja_core::provider`, because it reads a `Config` and nothing here does. |
| `auth.rs` | Provider credentials: environment first, then `auth.json` under the XDG data directory. Two kinds — an API key, and upstream's OAuth record (`{type, refresh, access, expires, accountId?, enterpriseUrl?, ...}`, where `expires: 0` means never). The file is shared territory, so nothing is ever dropped: entries of a type this build cannot read survive a rewrite, and so do the fields *inside* an OAuth record that it does not model, which upstream leaves open-ended by construction. Keys are upstream's names for the providers — ganja's `grok` is stored as `xai` — so the same file serves both tools. `Refresher` renews an expiring credential once per provider however many callers ask, the way upstream's per-plugin module-scoped promise does; the endpoint that does the renewing is a login flow's to supply through `RefreshOauth`. **P13** added `renew_oauth`, mirroring `set_oauth` but calling `Store::renew_oauth` (no stamp) — needed because a 401-forced MCP token refresh bypasses `Refresher::usable`'s own due-check entirely and cannot go through `Refresher`, but the write it persists is a refresh, not a login, and the file already draws that line for every other provider. `list_providers` reports **one row per place a credential lives**, environment first, with a stored row that an exported variable outranks carrying the variable's name in `shadowed_by` — the listing reports being outranked rather than hiding it, while `credential_for` remains the single place precedence is decided. |
| `auth/device.rs` | The RFC 8628 device grant, written once for every provider that speaks it: `start` returns the code to show, `poll` waits for it. Parameterised by endpoints, client, scope and **body encoding** — GitHub's endpoints take JSON where xAI's take a form. The classification order is load-bearing: the body is read first and the status consulted only when it named no error, because GitHub answers a pending poll `200` and xAI answers it `400`, and either upstream's rule taken alone breaks the other's flow. Ganja's loop is **bounded** by a deadline where upstream's Copilot loop is not, every wait is clamped to what is left of it, and a server-supplied interval that is not a positive number falls back to the default rather than becoming a busy loop. Time is injectable (`Clock`), as upstream's is, so a cadence is asserted rather than slept. **Nothing here writes a credential** — the caller stores what it returns, which is what makes a cancelled login structurally unable to leave anything behind. |
| `auth/pkce.rs` | PKCE (RFC 7636) and the other unguessable values a login rests on: the verifier, the `state`, the `nonce`. All three are 32 bytes of the operating system's entropy rendered as base64url — the construction Appendix B gives, 43 characters all inside the unreserved set — rather than upstream's biased sample over a 66-character alphabet. The S256 challenge is the digest of the verifier **string**, pinned against the RFC's published vector because a digest over the wrong input is only discovered by the token endpoint, at the end of a flow the person has already finished. |
| `auth/loopback.rs` | The bounded, cancellable listener an OAuth redirect comes back to. `127.0.0.1` only, one callback then stop, a deadline and a `CancellationToken`, and `/cancel`. **`state` is validated first and unconditionally** — missing, wrong or given twice is `400` and ends the wait — so nothing in a request that cannot prove it belongs to this login is read out of it. The pages it serves are built at compile time from words it owns, so no value out of the query ever reaches a browser. Provider-agnostic, and **it cannot write to the credential store**. |
| `auth/grok.rs` | xAI's two logins and their shared refresh. `PROVIDER_ID` is the one source of ganja's name for the provider — `grok` here, `xai` on disk via `storage_key`. The **browser flow** (`browser_flow`/`browser_flow_at` → `BrowserFlow::start` → `Browser::wait`) drives the loopback listener on **port 56121 exactly** — the host:port pair is part of xAI's client registration, so a port that cannot be bound is reported with the two ways out rather than silently swapped — and publishes `plan=generic` (without it the account portal refuses this client) and `referrer=opencode` alongside the S256 challenge, `state` and `nonce`. The **device flow** is the one that needs no browser here at all. Both end at one `credential_from`, so both store the same bytes. The refresh token **rotates**, and the new one is stored with the old kept only when the endpoint sent none. The error split is the point: a 4xx from the token endpoint is `ReauthRequired` (log in again), anything that never reached it — and a 5xx — is `RefreshUnavailable` (try again). `reason` carries a status and an error code, never a body and never a token. |
| `auth/openai.rs` | The ChatGPT login: a browser flow through the loopback listener and a device flow that is *not* RFC 8628 — the pending signal is a `403`/`404`, and the server mints the PKCE verifier — plus the `RefreshOauth` that renews the result. A 4xx from the token endpoint is `ReauthRequired` and everything else, `429` included, is `RefreshUnavailable`. The account id is base64url-decoded out of the `id_token` payload with **no signature check**, as upstream: a routing hint, never a trust decision. **Stores nothing** — the caller does. Shares the `openai` storage key with an OpenAI API key, so each login replaces the other. This is also the one place the auth→provider edge runs: its redirect check calls `provider::reachable_in_the_clear`. |
| `auth/mcp_oauth.rs` | **P13**: OAuth for a remote MCP server — RFC 8414 authorization-server discovery against the server's own origin, RFC 7591 dynamic client registration (minimal, falling back to a fixed public client id when a server names no registration endpoint), then `pkce`/`loopback` exactly as `openai.rs`'s browser login already runs them; neither module knows or cares which provider is asking. `Login`/`Browser::wait`/`Refresher` (a `RefreshOauth` impl reading `token_endpoint`/`client_id` back out of `OauthCredential::extra` rather than holding either — one stateless value serves every oauth-configured server). Storage rides the existing store at a reserved `mcp:<server>` key (`storage_key` passes the prefix through unchanged); **nothing here writes to the credential store**, matching every sibling login in this module. Deliberately minimal: no resource-metadata discovery, no scope requested (`oauth: {}` carries none to ask with), no per-request reactive re-authorization — all named follow-ups, not oversights. No upstream `opencode` counterpart at all — the v1.18.13 checkout refuses the `oauth` config key by name (**D466**). |
| `auth/copilot.rs` | GitHub Copilot's device login, public or enterprise. Two things are unlike every other provider: the GitHub OAuth token **is** the credential (same string in `refresh` and `access`, no second exchange anywhere in the pin), and `expires: 0` means **never**, not expired — so this module implements **no `RefreshOauth` at all**, because there is no endpoint to call and a stub would invite a caller to believe otherwise. `Deployment` carries which GitHub it is; `normalize_domain`/`api_base_for` derive the endpoints and the API base from whatever spelling a person typed. |
| `catalog.rs` | Context windows, max output and pricing, from a fetched catalog cached under the XDG **cache** directory, falling back to a compiled-in snapshot that never fails. `RwLock<Arc<_>>` behind the accessor functions, so `refresh` swaps the whole table. Per-provider default models stay compiled in — the published catalog has no such concept. A default is per *vendor*, which is one too few for OpenAI: its two backends serve different sets, so a ChatGPT seat takes `provider::responses::SUBSCRIPTION_DEFAULT` instead and this table's `openai` row is the **key** wire's default. A fetched payload names providers upstream's way, so its keys are read through `auth::provider_id_for_storage_key` on the way in (`xai` becomes `grok`): every consumer of this table holds a `Provider::id`, and a row filed under the other name is a turn nothing can price. `carries` is the second of the two tiers `provider::PROVIDERS` describes: selectable is what a session may run as, cataloged is the narrower set with rows here. The table test holds the obligation one way — a cataloged provider owes a priceable default, an uncataloged one owes no default at all — with each shipped wire's own default pinned beside that wire. |
| `atomic.rs` | Crate-private. Writing a sibling and renaming it into place, which is how the catalog cache is replaced. **A recorded duplication:** `ganja-permission` and `ganja-tui` keep their own copies of the same thirty lines, for the same reason — a crate that writes one kind of file does not reach sideways for a helper. The engine's copy went away with its only caller, which was the catalog. Read the module's note before changing any of them. |

## For AI Agents

### Working In This Directory

- **The vendor picks the wire, not the credential.** Everything filed under `openai` speaks Responses whether it authenticates with a key or a stored ChatGPT login. What the credential picks is which *backend* the request goes to and what it carries beside the bearer — and that decision is `ganja_core::provider::openai_provider`'s, on the other side of this crate's edge, because it is selection.
- **A login stores nothing.** Every flow returns a credential or an error; the caller writes it down. That is what makes "a cancelled login left nothing behind" a fact about which functions exist rather than a claim about which branches ran.
- **`expires: 0` means never expires, not expired in 1970.** `OauthCredential::needs_refresh` owns that question and nothing else re-decides it.
- **Nothing in `auth.rs` may drop an entry it cannot read.** `auth.json` is shared with upstream; an unrecognised credential type, and an unmodelled field inside a record this build does understand, both survive a rewrite untouched.

### Testing Requirements

Unit tests sit in `#[cfg(test)] mod tests` at the bottom of each module. There are no `tests/*.rs` binaries here — see the crate's `AGENTS.md` for why — but `tests/fixtures/` holds the captured event streams those unit tests replay, and `ganja-core`'s HTTP suites read the same files.

### Common Patterns

- A test that needs a credential store redirects `XDG_DATA_HOME`, so it can neither read nor write the real user's `auth.json`.
- Nothing may render a whole API key. `Presented::expose` is the single call site, and a test canary (`ganja-core/tests/secrets_env.rs`) proves a failed request logs nothing resembling one.
