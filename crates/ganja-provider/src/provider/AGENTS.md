# provider

## Purpose

Sources of assistant text. A provider turns a `ChatRequest` into a stream of `ProviderEvent`s; the engine maps those onto the protocol frontends see. Nine ids ship (`PROVIDERS`), over **five** distinct request/response mappings: a fake one for demos and tests, Anthropic Messages, OpenAI-compatible chat completions, the Responses API, and the Connect wire cursor's agent backend speaks. The other four are those mappings under another name — grok is xAI's chat-completions endpoint and copilot is GitHub's, each a base URL and a credential source over `openai.rs` (with a header set as well for Copilot); openrouter rides the Responses machinery at that vendor's own base; and the two zen tiers dispatch **per model** across three of the mappings off the catalog row's npm hint (**D488**). Every SSE wire shares the same shape — build a request, retry it while it has not started answering, split the `text/event-stream` body into frames, map those onto events — so everything except the mapping lives in `../provider.rs`, the module this directory hangs off. Cursor is the one exemption, and holds it three times: Connect envelopes rather than SSE frames, its own retry loop around a body that cannot be replayed, and its own fold, because its duplex answers the server mid-body. It is **not** exempt from the credential's bounds — the shared client, the retry driver, and `shielded`, which every wire's failures cross.

**The vendor picks the wire, not the credential.** Everything filed under `openai` — an API key and a stored ChatGPT login alike — speaks Responses, because upstream's plugin routes every model of that vendor through it with no reference to the credential at all (`plugin/provider/openai.ts:185`). What the credential still picks is which *backend* the request reaches and what it carries: `ganja_core::provider::openai_provider` builds one `ResponsesProvider` against `api.openai.com` with nothing but a bearer, or one against the ChatGPT codex backend with three more headers and the seat's model allow-list. That dispatch is selection's, on the far side of this crate's edge. `openai.rs` is therefore no longer that vendor's provider; it is the wire grok and copilot ride, and the shape any other OpenAI-compatible endpoint would.

## For AI Agents

### Working In This Directory

- **Failures have exactly two channels, and neither is a completed turn.** A request that never starts streaming fails the call to `Provider::stream`; one that dies mid-stream yields `ProviderEvent::Failed`, which is terminal — nothing follows it. That variant is what keeps a body that stopped arriving from reading as a model that finished talking.
- **Retry only before the first byte.** Once a provider has started streaming, replaying the request would either duplicate text already rendered or silently restart the model. Failures after that point are reported, not retried.
- **Where a credential can travel is bounded here, not in the individual providers**, because all three bounds are shared:
  - *No redirects.* `reqwest` strips `Authorization` across hosts but knows nothing about Anthropic's `x-api-key`, so a 3xx from a hijacked endpoint would hand the key to whatever it names. These are one-shot `POST`s that never legitimately redirect.
  - *https, or loopback.* The base URL is environment-controlled, and plain HTTP anywhere else puts the key on the wire in the clear. The check compares a `url::Host`, not a string.
  - *`system-proxy` is on deliberately.* `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` redirect provider traffic, which is frequently the only way a corporate network is reachable — but it is a trust boundary, and it is documented as one.
- **The SSE decoder must tolerate anything.** Unknown event types are logged and skipped, never panicked on.
- Adding a provider means adding it to `PROVIDERS` here, to `ganja_core::provider::select`'s match, and to the catalog's default-model table **and its snapshot**, or a session naming it has no model to ask for and no cost to report. `catalog.rs`'s own table test fails the build if you do one and not the other. A provider that shares an existing id — `responses.rs` shares `openai`'s — adds none of those, and instead joins the dispatch that reads a credential *kind*.
- **Two tiers, and neither implies the other.** *Selectable* is what a session may run as — `PROVIDERS` plus whatever a config's `provider` table declares. *Cataloged* is what `catalog::carries` says has rows. Every configured endpoint is selectable and uncataloged; so is a wire that ships before its rows do. An uncataloged session is not broken: it takes whole turns, with auto-compaction off, no cost, and its own model for the title.
- **A row with no price can be the honest row.** A subscription seat is billed by the month, so a Copilot row carries zeros and the status bar shows no cost while the token counters — which is what a quota is actually spent against — still show. `catalog.rs`'s table test excuses that by *provider name* rather than by `price == 0.0`, so a row anybody merely forgot to fill in still fails, and a seat row that grew half a price fails too.
- **One vendor can have two backends, and the credential picks.** `ganja_core::provider::openai_provider` sends a session with an API key to the platform and one with only a stored ChatGPT login to the codex backend, which is upstream's arrangement too (`plugin/openai/codex.ts:331`, `:356`, both branching on `auth.type !== "oauth"`). Both are built by this directory's `ResponsesProvider` constructors, so nothing about either — including which error a bad base URL produces — is that dispatch's to change.
- **A credential is resolved per request, not captured at construction.** `CredentialSource` is the seam: a key resolves to itself, and an OAuth credential goes through `auth::Refresher::usable` — which reads the store, renews only when the credential is due, and holds concurrent callers to one exchange because xAI's and ChatGPT's refresh tokens both rotate. What comes back is a `Resolved`, not just a secret: a ChatGPT credential also names the account the request is billed to, and that has to come from the same read the token did or a renewal can leave the two disagreeing. That is the position upstream's `fetch` override occupies, and it is why a renewal cannot live in the engine's `session.rs`: nothing there knows when a token died.
- **How a failed renewal is classified is load-bearing, not cosmetic.** A refusal (`AuthErrorKind::ReauthRequired`, and the rest of the taxonomy) is `ProviderError::Auth`, which is *not* retryable; a token endpoint that could not be reached (`RefreshUnavailable`) is `ProviderError::Transport`, which *is*. Retry applies exactly where a refresh sits, so folding the first into the second turns one expired grant into a storm against an identity provider, and folding the second into the first sends a dropped network through a browser login it did not need.
- **`expires: 0` means never expires, not expired in 1970.** The question a credential is asked is whether it has a deadline, never whether a zero is in the past; `OauthCredential::needs_refresh` owns that and nothing here re-decides it.

### Testing Requirements

Mapping is proved twice: unit tests here, and a suite serving recorded transcripts over a real loopback socket. Those socket suites live in the engine's crate, because what they assert is observable through it — `ganja-core/tests/http.rs` for the two key-authenticated wires, `ganja-core/tests/responses_wire.rs` and `ganja-core/tests/copilot_wire.rs` for the two subscription ones. Fixtures live here, in `../../tests/fixtures/*.sse`, and cover the cases that matter — happy path, truncated stream, mid-stream error, malformed frame, interleaved tool calls, a tool call cut short; the engine's suites reach across for them, because a recorded vendor transcript belongs beside the wire that parses it. A new provider or a new frame shape needs proving over a socket as well as in a unit test, whether the transcript lives in a fixture file or beside the suite that serves it.

Live vendor checks are opt-in (`GANJA_LIVE_TEST=1`, `-- --ignored`) and prove only what a socket cannot: that the header names, API version and model identifiers are still current.

### Common Patterns

- Environment variables are read through one helper so an unset variable, an empty variable and a non-UTF-8 variable behave the same everywhere.
- `ProviderError` is transport-agnostic on purpose: the same taxonomy has to fit a provider that never leaves the process and one that speaks HTTP.
- A server-run tool call arrives as an `openrouter:`-prefixed output item and becomes `ProviderEvent::ServerTool` — display-only, never a `ToolCall`, because OpenRouter already executed it (D489); the second reasoning-delta spelling (`response.reasoning.delta`, that vendor's own) maps beside OpenAI's with a response-scoped dedupe.
- Reasoning arrives on two channels and they are not the same thing: `ReasoningDelta` is thinking a person could read (now a protocol part of its own, `PartBody::ReasoningText` — the engine streams it into the transcript and every frontend draws it, but **no wire sends it back**), `ReasoningState` is thinking only the provider can read (`PartBody::Reasoning`, kept and handed back). A wire encoding a request drops the readable half and sends the sealed one: replaying both would be sending the same thought twice, once in a form nothing asked for.

## Dependencies

### Internal

`crate::protocol` (`Message`, `Usage`, `FinishReason`) and `crate::tool::ToolDefinition` (what the model is offered) — both re-exports, of `ganja-protocol` and `ganja-tool`; `crate::auth` (credential lookup) and `crate::catalog` (default models), which are this crate's own siblings. Nothing here may name `ganja-core`, and CI asserts the whole internal set rather than that one absence.

### External

`reqwest` (rustls, `stream`, `json`, `system-proxy`), `futures`, `secrecy`, `serde_json`, `tokio-util` (`CancellationToken`), `url`, `tracing`.
