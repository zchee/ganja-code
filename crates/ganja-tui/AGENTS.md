# ganja-tui

## Purpose

The ratatui frontend. It owns every pixel and no engine logic: terminal events become `ganja_core::Command`s, engine `Event`s become frames. Entry point is `run()` in `src/lib.rs`, which reads the config, resolves the key bindings, selects a provider, builds the `Engine` with the builtin tools, the project's permission rules, the agent roster, the MCP servers, the language servers, the working-tree snapshots `/undo` restores from, and both halves of the system prompt, starts the stale-read watcher over the files the session reads, loads the theme set — all before the terminal is taken over, so every refusal is readable — and then hands the engine to the `App` loop.

## Architecture

Hoisted out of the workspace root's `AGENTS.md` so that file stays inside Claude Code's 150,000-character context budget. The root keeps a summary and points here; this is where these decisions are stated in full.

**`ganja-tui`** — every pixel, no engine logic. It links `ganja-protocol` for the types it renders, `ganja-permission` for the stored rules it loads and hands to the engine, and `ganja-tool` for the one thing it runs in-process, the `@` menu's glob walk. One `tokio::select!` owns all mutable UI state; `App::handle` is the only mutator, which is what makes components testable without a terminal. Frames coalesce to 16ms for streaming bursts; a keystroke redraws immediately. Between the `EventStream` and that handler sits `escrepair.rs` (**D516**): crossterm commits a lone `ESC` the moment it is the last byte of a read, so an arrow key split across two reads once arrived as a phantom Esc — which cancels a running turn — plus literal `[D` in the composer; a bare Esc is now held 25ms and reconstructed into the CSI/SS3 key the parser would have produced unsplit, everything released honestly in arrival order on any mismatch or deadline, and only a split SGR-mouse fragment or paste marker swallowed rather than pasted. Where the terminal answers the kitty keyboard probe at startup, `DISAMBIGUATE_ESCAPE_CODES` is pushed instead (**D517**) — Esc then arrives as `CSI 27 u`, unsplittable, and the repair runs in passthrough — popped again on every exit including the panic hook, and popped/re-pushed around the external editor because the flag stacks are per screen buffer; `GANJA_DISABLE_TERM_PROBE` skips the probe, whose unanswered wait costs two seconds. Themes are loadable data (four ported from upstream, plus whatever `<config home>/themes/` holds), the palette and the `/` menu are two views of the same command set, `@` raises a file menu, `$` raises a skill selector (the Codex CLI's grammar, **D491**: a mention like `@`, never a line prefix — Tab/Enter complete `$name `, prose dollars like `costs $5` raise nothing because only a discovered name keeps the menu up, and `/skills` is the listing dialog whose Enter inserts the token), and a leading `!` hands the line to a shell. Both inline menus complete on Tab as well as Enter — the file menu inserts the selected path exactly as Enter does, the slash dropdown completes the buffer to the command name **without** running it (Claude Code's own screenshots; upstream's Tab dispatches the row like Enter, D446) — and Ctrl+L forces the next frame through a full redraw, the same `stale` flag the external editor's return path already sets (D445, no upstream counterpart). A complete command name standing alone in the composer shows its arguments dim after it (**D518**, Claude Code's presentation, paint only — the buffer a submit reads never contains it): `/team`'s hint is its own grammar and a bare `/team spawn` shows the one spelled `SPAWN_GRAMMAR`, a command file's is its frontmatter `argument-hint` — carried on its own `Definition` slot now, beside the palette fold that keeps a dropdown row informative before the name is complete — and the words typed after the name consume it front to back (the slot still being typed into included), the remainder standing beside the cursor until the grammar runs out or a word it has not got arrives. The slots a `/team` line has are also **completed** (**D519**, neither upstream's): the same dropdown box, titled after the slot, opens over what could fill it — the subcommand after `/team`, `spawn`'s flags minus the ones already given, the surface after `--backend`, the kind after `--agent` — and Tab or Enter replaces only the word under the cursor, with the space that ends the slot. The surfaces are `ganja_core::teammate::BACKENDS`, the one spelling the spawn door's refusal already lists, and the kinds are the registry's spawnable agents, so neither list can drift from the parser; nothing here validates, and a value typed past the menu is still refused by name on the far side. `/copy` and `/copy-message` put the conversation or the last reply on the clipboard — through arboard and upstream's OSC 52 escape both, so a copy lands even over ssh or tmux — pasted text arrives whole through bracketed paste, a drop or paste of one or more existing (or `file://`) paths becomes `@`-mentions instead of raw text (every token must resolve or the whole paste stays literal), Ctrl+V pastes a clipboard image as a PNG encoded in-process and attached through that same mention pipeline — shown in the composer as Claude Code's own `[Image #N]` token since 2026-08-15, the number mapped back to the saved file at send time while the token stays in the text; a Finder-style **file copy** is read off the pasteboard's file list *before* its decoy basename text — Claude Code reads the same metadata as `«class furl»` — its image files tokenized against the copied file itself, everything else classified as a drop would be; and an **empty** bracketed paste — Cmd+V over an image-only clipboard, where the terminal has no text to put inside the envelope — routes to the same clipboard chain, Claude Code's own mechanism for the system paste chord (D449; D111 now names only the long-paste-folding half still unbuilt), and a configured MCP server that cannot be reached is named in the status bar. The composer keeps upstream's prompt history (fifty entries on disk, walked with Up/Down from an empty or unedited buffer — and since 2026-08-20 every argument-bearing `/team` line typed joins it as typed, accepted or refused by the grammar, because the words leave the composer either way — a bare `/team` is the palette's door like every other UI command and is not — while a spawn decided in the `/team` dialog is remembered as the `/team spawn …` line it is equivalent to and a message to a member is not, since recalled into the composer it would go to the lead's own model), breaks lines on `shift+enter`/`ctrl+j`, and its `@` mentions name line ranges (`@file#5-9`) and attach images and PDFs, with a submit-time warning when the selected wire cannot carry one. ## For AI Agents

### Working In This Directory

- **Terminal restoration is an invariant, not a nicety.** `run()` restores on every exit path including panic: the hook installed here undoes mouse capture, then defers to the one `ratatui::try_init` installed, which leaves raw mode and the alternate screen. A new terminal mode must be undone the same way, or a crash leaves the user's shell unusable.
- The frontend keeps its own copy of the selected model so it can price a turn without reaching into the engine.
- Rendering is driven entirely by engine events. If the UI needs to show something the engine does not report, the fix is a protocol event in `ganja-core`, not local bookkeeping in the frontend.

### Testing Requirements

```sh
cargo test -p ganja-tui
cargo insta review     # after intentional visual changes
```

Components are tested without a terminal by feeding `AppEvent`s to `App::handle` and rendering into a `TestBackend`; screen assertions are `insta` snapshots under `src/snapshots/`.

### Common Patterns

Widget state lives in the component struct, never in a global; components expose `handle`-shaped methods that the app calls, so no component reaches back into the engine on its own.

## Dependencies

### Internal

`ganja-core` — for `Engine` and `catalog` pricing. `ganja-permission` — for the project's stored permission rules the frontend loads and hands to the engine (`Permissions`, `Project`), named directly so the core dependency stays about the engine. `ganja-protocol` — for `Command`, `Event` and the `Message`/`Part` model a transcript is built from, named directly rather than through the engine's re-export, because rendering takes the protocol and nothing else. `ganja-tool` — for the one thing this crate runs in-process: the `@` file menu's glob walk, which builds its own `ToolCtx` and a `FileTimes` of its own so nothing it touches enters the session's read log. `ganja-teammate-local` (**D538**, **D539**) — for the five pane and foreign-CLI teammate backends this crate assembles into a `Backends` (`ganja_teammate_local::backends(shell, share)`) and hands to `Engine::with_teammates`, plus the `tmux::{Server, TMUX_PANE}` and `reaper::{sweep, sweep_shims}` calls the frontend drives directly — named directly rather than reached through `ganja-core`, which may not name a crate above it.

### External

`ratatui` 0.30 + `ratatui-textarea` (editor widget), `crossterm` (feature enablement only), `tokio`, `futures`, `anyhow`, `unicode-width` (the chat viewport measures its own wrap widths rather than leaning on `Paragraph`), `serde_json` (rendering tool metadata), `pulldown-cmark` + `syntect` (assistant-reply markdown and fenced-code highlighting), `arboard` (clipboard, text only), `insta` (dev).
